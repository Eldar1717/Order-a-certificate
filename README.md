# Система мониторинга готовности справок для колледжа

Веб-приложение для автоматизации процесса заказа и отслеживания статуса справок в учебном заведении.

## 🚀 Возможности

### Для студентов:

* **📋 Заказ справок** - простая форма с указанием ФИО, даты рождения, места требования
* **👀 Просмотр статусов** - мониторинг всех заказанных справок
* **🔍 Поиск справок** - фильтрация по ФИО студента
* **📊 Проверка статуса** - быстрая проверка по номеру справки
* **🆓 Свободный доступ** - не требуется регистрация или пароль

### Для секретарей:

* **👨‍💼 Управление статусами** - изменение статусов справок ("в работе"/"готово")
* **📈 Статистика** - обзор количества справок по статусам
* **🔧 Фильтрация** - поиск по ФИО, месту требования, статусу
* **🔐 Защищенный доступ** - вход по паролю

## 🎨 Дизайн и визуал

Интерфейс собран на небольшой дизайн-системе в одном файле `static/style.css` —
без фреймворков и сборки.

### Что использовано

* **Дизайн-токены** — палитра, радиусы, тени и типографика заданы CSS-переменными
  в `:root`, поэтому тему можно менять в одном месте.
* **Единая сетка** — контейнер 1200px, «мягкие» карточки с тонкой рамкой и
  многослойными тенями, единый шаг отступов.
* **Цветовые статусы** — «в работе» / «готово» / «отклонено» кодируются цветом
  на трёх уровнях: полоса карточки, бейдж и трекер этапов. Это читается даже
  боковым зрением.
* **Трекер прогресса** — на карточке справки видно весь путь: Заказ → В работе → Готово.
* **Иконки** — инлайновый SVG-набор (`templates/_icons.html`), без внешних библиотек
  и лишних запросов.
* **Состояния интерфейса** — загрузка (скелетоны), пустые состояния с подсказкой
  и действием, всплывающие уведомления вместо `alert()`.
* **Доступность** — контраст, фокус-обводки, `aria`-атрибуты, skip-link,
  поддержка `prefers-reduced-motion`.
* **Адаптивность** — мобильная навигация со скроллом, перестройка форм и карточек
  в одну колонку, «липкая» первая колонка таблицы.
* **Печать** — `@media print` убирает навигацию и тени, чтобы карточку справки
  можно было распечатать.

### Поведение интерфейса

* **Часовой пояс** — в базе время хранится в UTC, на экран выводится в поясе
  из переменной окружения `APP_TZ` (по умолчанию `Europe/Moscow`).
* **KPI-карточки в панели секретаря кликабельны** — работают как быстрый фильтр
  по статусу (доступно и с клавиатуры).
* **Копирование номера** — кнопка «Копировать» на странице подтверждения и проверки статуса.
* **Форма заявки** — нативная валидация, запрет даты рождения в будущем и защита
  от повторной отправки (кнопка блокируется на время запроса).

### Как менять оформление

| Задача | Где менять |
| --- | --- |
| Основной цвет, фон, радиусы, тени | переменные в `:root` (`static/style.css`) |
| Цвета статусов | блоки `.status-badge`, `.stat-card--*`, `.certificate-card[data-status]` |
| Новые иконки | словарь `_icons` в `templates/_icons.html` |
| Тексты подсказок и микрокопирайт | соответствующие `templates/*.html` |

## 📱 Сенсорный киоск (Windows + браузер)

Интерфейс адаптирован под большой сенсорный монитор и режим киоска: крупные
элементы управления, отклик на касание и встроенная экранная клавиатура —
внешняя клавиатура и системная экранная клавиатура Windows не нужны.

### Экранная клавиатура

* Появляется автоматически при касании поля ввода (на сенсорных устройствах).
* Раскладки **РУС/ENG**, Shift (липкий), Caps, пробел, удаление символа.
* **Цифровой блок** включается сам для числовых полей и номера справки;
  для целых полей точка и минус скрыты, первая цифра заменяет значение по умолчанию.
* Кнопки «Предыдущее / Следующее поле» — переход между полями без мыши.
* Поля с нативным вводом (дата) клавиатуру не вызывают — используется системный
  календарь, а нажатия не «проваливаются» в предыдущее поле.
* Физическая клавиатура и мышь продолжают работать; при наборе с физической
  клавиатуры экранная автоматически скрывается (вернуть — тап по полю).

### Управление через адресную строку

| Параметр | Действие |
| --- | --- |
| `?vk=on` / `?vk=off` | принудительно включить или выключить экранную клавиатуру |
| `?kiosk=1` | режим киоска: без выделения текста, без «резинки», сброс на главную по бездействию |
| `?idle=300` | таймаут бездействия в секундах (по умолчанию 180, минимум 20) |

Выбор режима клавиатуры запоминается в `localStorage`. Сбросить настройку можно
кнопкой «Экранная клавиатура» в подвале страницы.

### Запуск в киоске

Сервер (Windows):

```bat
pip install -r requirements.txt
waitress-serve --listen=0.0.0.0:5000 app:app
```

Браузер в киоске (Chrome или Edge, ярлык в автозагрузке):

```bat
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --kiosk --app=http://localhost:5000/?kiosk=1 ^
  --window-size=1920,1080 --force-device-scale-factor=1 ^
  --no-first-run --no-default-browser-check --disable-infobars ^
  --disable-pinch --overscroll-history-navigation=0
```

Для Edge замените путь на `msedge.exe`.

Что ещё стоит настроить в самой Windows:

* **Параметры → Устройства → Ввод** — отключить «Показывать экранную клавиатуру
  при отсутствии клавиатуры», иначе поверх интерфейса появится системная.
* **Параметры → Система → Питание** — отключить сон и гашение экрана
  (`powercfg /change standby-timeout-ac 0`, `powercfg /change monitor-timeout-ac 0`).
* **Автозапуск** — ярлык браузера в `shell:startup`.
* Для защиты от выхода в рабочий стол используйте «Назначенный доступ»
  (Assigned Access) в Windows или оболочку киоска.

## 🛠 Надёжность: автоперезапуск и удалённая диагностика

Приложение рассчитано на три компьютера: **киоск студента**, **сервер** и
**рабочее место секретаря**. Если сервер «упал», киоск не должен показывать
ошибку браузера, а секретарь — бегать в серверную.

### Уровень 1. Служба Windows (основной способ)

Служба поднимает приложение при старте компьютера и перезапускает его через
5 секунд после любого падения.

```powershell
# от имени администратора, nssm.exe положите в scripts\ (nssm.cc/download)
powershell -ExecutionPolicy Bypass -File scripts\install-service.ps1
```

Что настраивается: автозапуск, перезапуск при падении (`AppExit Restart`),
задержка 5 с, логи в `scripts\logs\app.out.log` / `app.err.log` с ротацией.
Удалить службу: `scripts\install-service.ps1 -Uninstall`.

### Уровень 2. Watchdog (если служба не подходит)

`scripts\watchdog.ps1` сам запускает приложение и следит за `/healthz`.
Ловит не только падение процесса, но и **зависание** (процесс жив, но не отвечает):

```powershell
# автозапуск при входе пользователя + запуск сейчас
powershell -ExecutionPolicy Bypass -File scripts\watchdog.ps1 -InstallStartup -Start
```

Защита от «шторма»: пауза при частых падениях, лимит 10 перезапусков в час,
лог `scripts\logs\watchdog.log`.

Если служба уже стоит, для контроля зависаний добавьте разовую проверку
в Планировщик заданий (каждые 3 минуты):

```powershell
schtasks /create /tn "CollegeCertificates-Watchdog" /sc minute /mo 3 /ru SYSTEM ^
  /tr "powershell -ExecutionPolicy Bypass -File C:\apps\certs\scripts\watchdog-check.ps1" /f
```

`watchdog-check.ps1` опрашивает `/healthz` и при отсутствии ответа перезапускает
службу; если службы нет — завершает зависший процесс по порту.

### Уровень 3. Перезапуск из интерфейса

* **Панель секретаря** — полоска «Сервер работает · без сбоев 2 ч 14 мин»
  с обновлением раз в 30 секунд и ссылкой на страницу сервера.
* **Страница `/admin`** — состояние (PID, uptime, база, режим, последний
  перезапуск и его причина) и кнопка «Перезапустить приложение» с подтверждением.
  Доступна по сессии секретаря или по токену — можно открыть с телефона:

  ```
  http://SERVER:5000/admin?token=ДЛИННЫЙ_ТОКЕН
  ```

* **API** для мониторинга и скриптов:

  | Метод | Адрес | Назначение |
  | --- | --- | --- |
  | GET | `/healthz` | проверка живости (200 — всё хорошо, 503 — проблема с БД) |
  | GET | `/api/admin/status` | подробный статус (секретарь или токен) |
  | POST | `/api/admin/restart` | перезапуск; тело `{"reason": "…"}` |

  ```bash
  curl -X POST -H "Content-Type: application/json" \
       -d '{"reason": "не отвечает"}' \
       "http://SERVER:5000/api/admin/restart?token=ДЛИННЫЙ_ТОКЕН"
  ```

Перезапуск выглядит так: приложение отвечает `{"ok": true}`, через 1.5 секунды
корректно завершается, служба (или watchdog) поднимает его заново, а страница
сама ждёт восстановления и перезагружается.

### Переменные окружения сервера

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `RESTART_TOKEN` | пусто | токен удалённого перезапуска; пусто — доступ только через сессию секретаря |
| `RESTART_MODE` | `exit` | `noop` — только логировать запрос, не останавливать процесс (для отладки) |
| `RESTART_DELAY` | `1.5` | пауза перед завершением процесса, секунды |
| `SECRETARY_PASSWORD` | `secret123` | пароль секретаря |
| `SECRET_KEY` | `your-secret-key-here` | секрет сессий; **задайте постоянный**, иначе сессии слетают при перезапуске |
| `APP_ENV` | `prod` | метка окружения в статусе |
| `PORT` | `5000` | порт приложения |
| `APP_TZ` | `Europe/Moscow` | часовой пояс выводимых дат |

Пример для службы: переменные задаются в `scripts\run-server.bat` или через
`nssm set CollegeCertificates AppEnvironmentExtra RESTART_TOKEN=...`.

### Если студент видит «Сервер обновляется»

Так выглядит штатное поведение при перезапуске: страница каждые 15 секунд
проверяет `/healthz`, при двух неудачах показывает экран ожидания со счётчиком,
а после восстановления автоматически перезагружается. Никаких ошибок браузера
и кнопки «Обновить» посетителю нажимать не нужно.
